# 계약 (shared)

서비스·모듈 사이의 약속을 둔다. 제공하는 쪽은 이 문서대로 구현하고, 쓰는 쪽은 이 문서를 보고 Feign 클라이언트나 가짜 구현(Mock)을 만든다. 구현 코드가 아니라 이 문서가 기준이다.

| 경로 | 내용 |
|---|---|
| [conventions.md](conventions.md) | 모든 API가 따르는 공통 규약: 헤더, 응답·오류 형식, 시각·ID 타입, 멱등 키 |
| `internal-api/{제공 도메인}.md` | 서비스 간 `/internal/**` API. 제공하는 쪽 기준으로 파일을 나눈다 |
| `modules/` | 같은 서비스 안의 모듈 간 인터페이스 |

Kafka 메시지 스키마는 Phase 2에서 `events/`에 추가한다.

## 계약 변경 흐름

1. **이슈:** 계약 이슈 양식으로 초안을 올린다. 제공·소비 담당자, 요청·응답, 오류, 멱등성, 타임아웃·재시도를 적고 영향받는 담당자를 태그한다.
2. **합의:** 담당자들이 이슈 댓글로 확인한다. 의견이 다르면 여기서 조정한다.
3. **계약 PR:** 합의한 내용을 이 폴더에 반영한다. 문서만 담아 작게 올리고 바로 머지한다. 계약 항목의 `상태`를 `합의 (#이슈)`로 바꾼다.
4. **병렬 개발:** 제공하는 쪽은 API를 구현하고, 쓰는 쪽은 문서를 보고 Feign 클라이언트나 Mock을 만들어 동시에 개발한다.
5. **구현 PR:** 각자 올린다. 제공하는 쪽 구현 PR이 머지되면 `상태`를 `구현됨 (#PR)`으로 바꾼다. 개발 중 계약을 바꿔야 하면 1번으로 돌아간다. 문서와 다르게 구현하지 않는다.

계약 항목마다 `상태`와 `변경 이력`을 둔다. 양식은 [_template/contract.md](../_template/contract.md)다.

| 상태 | 뜻 |
|---|---|
| 초안 | 제공하는 쪽이 제안했다. 쓰는 쪽은 아직 이 내용에 기대지 않는다 |
| 합의 (#이슈 또는 Notion) | 담당자들이 확인했다. 양쪽이 이 문서로 개발한다 |
| 구현됨 (#PR) | 제공하는 쪽 구현이 머지됐다 |
