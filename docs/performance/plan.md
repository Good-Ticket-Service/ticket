# 공연(performance-service) 구현 계획

- 상태: 작성 중
- 담당: 박의연
- 기간: 2026-10-28 ~ 2026-11-13 개발, 11/19 발표

공연 좌석 예매 MSA에서 공연장·공연·회차·가격과 공개 조회, 판매 검증을 맡는다. MVP는 동기 방식(Feign)과 단일 트랜잭션으로 먼저 동작하게 만든다. 이후 부하 테스트로 병목을 찾아 개선하고, 좌석 준비 연동을 Kafka 비동기로 바꿔 전후를 수치로 비교한다.

## 1. 목표

| 목표 | 내용 | 성과 지표 | 이번 범위 |
|---|---|---|---|
| G1 조회 성능 | 예매 오픈 직후 몰리는 공개 상세·회차·좌석 배치 조회와, 예매 요청마다 호출되는 판매 검증을 버티게 한다 | p95 응답 시간, 처리량(RPS), 요청당 쿼리 수, DB CPU·커넥션 사용량 | 측정 → 개선 1개 → 재측정 |
| G2 판매 정합성 | 공연·회차 상태 전이와 좌석 준비 연동이 실패해도 데이터가 어긋나지 않게 한다. 좌석 준비를 Feign에서 Outbox + Kafka로 전환한다 | 장애 주입 시 불일치 0건, 회차 등록 응답 시간, 좌석 서비스 장애 시 공연 API 영향, 복구 시간 | Kafka 전환과 Feign 대비 비교 |
| G3 검색 품질 | PostgreSQL 검색을 기준선으로 두고 Elasticsearch(Nori)와 비교한다. 색인 동기화는 G2의 Outbox 구조를 쓴다 | 상위 결과 적합도, 검색 실패율, 색인 반영 지연 | 향후 과제 |
| G4 자연어 검색 | "가족이 다 같이 볼 뮤지컬"처럼 자연어 질문을 조건 필터(장르, 관람 등급, 지역, 날짜)와 의미 검색으로 바꾼다. 필요하면 추천 이유를 생성한다(RAG) | 조건 준수율, 추천 적합도 | 향후 과제 |

G1과 G2를 이번 기간에 완주하고, G3·G4는 발표에서 향후 계획으로 제시한다.

## 2. 작업 단계

모든 고도화는 아래 흐름을 따른다. 측정하지 않은 개선은 하지 않는다.

```text
MVP 기능 개발 → 부하 테스트 → 성능 측정 → 병목 발견 → 개선 → 재측정
```

| 영역 | 1. MVP | 2. 측정 | 3. 개선 |
|---|---|---|---|
| 좌석 준비 연동 | Feign 동기 호출, 같은 requestId로 서버 자동 재시도 | 회차 등록 응답 시간, 좌석 서비스 지연·장애 시 영향 | Outbox + Kafka 비동기 발행, 결과 이벤트 소비, 중복 수신 처리 |
| 공개 조회 | JPA·QueryDSL로 DB 직접 조회 | p95, 처리량, 요청당 쿼리 수(N+1), 실행 계획(`EXPLAIN ANALYZE`) | 인덱스·쿼리 개선 또는 캐시. 캐시는 공개·수정·취소·삭제 시 무효화 규칙을 함께 정한다 |
| 판매 검증 | 단일 트랜잭션 조회 | 예매 부하 중 호출 응답 시간 | 측정 결과에 따라 조회 최적화 또는 캐시 |
| 상태 변경 | 부모 행 잠금(`SELECT ... FOR UPDATE`)과 낙관적 잠금(version) | 동시 요청 테스트로 충돌·대기 확인 | 측정 결과에 따라 잠금 범위 조정 |

측정은 같은 데이터·같은 부하 조건에서 개선 전후를 비교한다. 지표는 Prometheus·Grafana(팀 Compose 포함)와 k6 결과로 남긴다.

## 7. 향후 과제

- G3 Elasticsearch 검색: 근거는 데이터 양이 아니라 검색 품질(공연명·출연진·설명 통합 검색, 제목 일치 우선, 한국어 형태소 분석, 오타·동의어)이다. PostgreSQL 검색과 같은 검색어로 비교한 뒤 도입한다. DB를 원본으로 두고 G2의 Outbox 이벤트로 색인을 동기화하며, 실패 재시도와 전체 재색인을 준비한다.
- G4 자연어 검색: 명시된 조건(장르, 관람 등급, 지역, 날짜)은 필터로 보장하고, 분위기·취향은 의미 검색 순위에 반영한다. 현재 스키마의 `genre`, `age_rating`, `cast_info`, `description`, 공연장 `region`으로 조건 해석이 가능하다. 추천 근거를 위해 시드 데이터의 `description`을 충실하게 만든다. "가족"을 "어린이 포함"으로 단정하지 않는다.
- P2 API 8개, 회차 취소(보류).
